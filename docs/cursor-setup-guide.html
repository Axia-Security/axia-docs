Cursor Setup Guide

Send the prompts your developers submit to Cursor's AI to Axia, so sensitive data pasted into an AI coding agent is detected.

What you'll have at the end

A Cursor hook on each developer machine that forwards every submitted prompt to Axia, using the Webhook URL and Webhook Secret Axia gives you on the Connect page.

How it works

  • Cursor has no cloud feed of prompts: its Admin API, audit logs and webhooks leave prompt text out. So capture happens on the developer's machine. A beforeSubmitPrompt hook runs each time a developer sends a prompt and posts it to your Axia Webhook URL.
  • Axia receives only the prompt text plus the conversation ID, workspace folder and the developer's identity. It does not receive the AI's replies or your code.
  • The hook never blocks or slows the developer. It always tells Cursor to continue, sends in the background, gives up after 5 seconds, and does nothing if it is not configured.
  • Prompts from one conversation are grouped into one case in Axia.

Prerequisites

  • An Admin account in Axia, to open the Connect page
  • A Cursor version with hooks support
  • Developer machines on macOS or Linux, with python3 on the PATH (standard library only, nothing to install). Windows is not supported yet.
  • Developer machines can reach your Axia Webhook URL over HTTPS (directly, or through your VPN)
  • For a fleet rollout: an MDM or configuration management tool (Jamf, Kandji, Intune, Ansible…), or Cursor Enterprise for hooks managed from the Cursor team dashboard
Tell your developers

Capturing prompts is monitoring of what employees type. Treat it as a policy and consent matter, tell developers before you turn it on, and check it fits how you use Cursor Privacy Mode.

1 Connect Cursor in Axia

  1. In Axia, open Connect and find Cursor under AI coding.
  2. Click Connect.
  3. Axia shows a Webhook URL and a Webhook Secret. Copy both.
Value to copyLooks like
Webhook URLhttps://<your-axia-host>/api/v1/webhooks/cursor
Webhook SecretA long random string
The secret is shown once

Save the Webhook Secret in your password manager now. If you lose it, open the connection and click Regenerate secret, then update every machine: the old secret stops working.

2 Check the Webhook URL is reachable

From a developer machine, send a test prompt. Replace the two values with yours:

curl -i -X POST "https://<your-axia-host>/api/v1/webhooks/cursor" \
  -H "Content-Type: application/json" \
  -H "X-Webhook-Secret: <webhook-secret>" \
  -d '{"event":"user_prompt_submit","timestamp":"2026-01-01T00:00:00Z","project_dir":"/tmp",
       "data":{"user_prompt":"Axia connectivity test","session_id":"setup-test","prompt_id":"1","user":"you@yourcompany.com"}}'

You should get HTTP 202 with "status":"accepted". If not, see Troubleshooting.

3 Set the URL and secret on each machine

The hook reads two environment variables. Cursor must see them when it starts, so set them for the user's login session, not only in a shell profile: Cursor opened from the Dock or an app launcher does not read ~/.zshrc or ~/.bashrc.

VariableValue
AXIA_WEBHOOK_URLThe Webhook URL from step 1
AXIA_WEBHOOK_SECRETThe Webhook Secret from step 1
AXIA_USER_EMAIL (optional)The developer's work email. See Which user is the prompt attributed to?

macOS

Push a LaunchAgent with your MDM that runs at login, for example /Library/LaunchAgents/com.yourcompany.axia-env.plist:

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0"><dict>
  <key>Label</key><string>com.yourcompany.axia-env</string>
  <key>RunAtLoad</key><true/>
  <key>ProgramArguments</key><array>
    <string>/bin/sh</string><string>-c</string>
    <string>launchctl setenv AXIA_WEBHOOK_URL "https://<your-axia-host>/api/v1/webhooks/cursor"; launchctl setenv AXIA_WEBHOOK_SECRET "<webhook-secret>"</string>
  </array>
</dict></plist>

Linux

Add the variables to /etc/environment (or a file in /etc/environment.d/), then have the user log out and back in.

4 Deploy the hook

Cursor reads hooks.json from several places. Use the enterprise location for production: developers cannot remove it. Use the per-user location to try it on your own machine first.

ScopePathUse for
Enterprise (macOS)/Library/Application Support/Cursor/hooks.jsonFleet rollout by MDM
Enterprise (Linux)/etc/cursor/hooks.jsonFleet rollout by MDM
TeamCursor team dashboard (Cursor Enterprise)Fleet rollout without MDM
User~/.cursor/hooks.jsonTesting on one machine

The file contents (if a hooks.json already exists there, add the beforeSubmitPrompt entry to it):

{
  "version": 1,
  "hooks": {
    "beforeSubmitPrompt": [
      {
        "timeout": 10,
        "failClosed": false,
        "command": "python3 -c \"import os,sys,json,shutil,subprocess,getpass,datetime as dt,urllib.request; s=os.environ.get('AXIA_WEBHOOK_SECRET',''); url=os.environ.get('AXIA_WEBHOOK_URL',''); (s and url) or sys.exit(0); d=json.load(sys.stdin); e=(subprocess.run(['git','config','user.email'],capture_output=True,text=True).stdout.strip() if shutil.which('git') else ''); r=d.get('workspace_roots') or ['']; u=os.environ.get('AXIA_USER_EMAIL') or e or d.get('user_email') or getpass.getuser(); body=json.dumps({'event':'user_prompt_submit','timestamp':dt.datetime.now(dt.timezone.utc).isoformat(),'project_dir':(r[0] if r else ''),'data':{'user_prompt':d.get('prompt',''),'session_id':d.get('conversation_id',''),'prompt_id':d.get('generation_id',''),'user':u}}); req=urllib.request.Request(url, data=body.encode(), headers={'Content-Type':'application/json','X-Webhook-Secret':s}, method='POST'); os.fork() or (os.setsid(), urllib.request.urlopen(req,timeout=5), os._exit(0))\" 2>/dev/null; echo '{\"continue\": true}'"
      }
    ]
  }
}
Keep failClosed off

With "failClosed": false, a network error or a missing python3 never stops a developer's prompt. The hook also always prints {"continue": true}, so Axia only observes: it never blocks.

Restart Cursor after deploying. In Cursor's settings, the Hooks tab lists the hook and shows its output if it fails.

Which user is the prompt attributed to?

The hook works out the developer's identity in this order:

  1. The AXIA_USER_EMAIL environment variable, if set
  2. The developer's git config user.email
  3. The email of the account signed in to Cursor
  4. The operating system login name

Git email comes before the Cursor account so that one person's Cursor and Claude Code prompts match up in Axia.

5 Verify

  1. On a machine with the hook, open Cursor and send any prompt to the AI.
  2. In Axia, the Cursor connection shows a recent event, and the prompt is analyzed. A prompt containing test sensitive data (for example a fake card number) should open a case.

Troubleshooting

SymptomCauseFix
Test returns 404 Unknown sourceCursor is not connected in Axia, or the URL is wrongConnect Cursor (step 1) and copy the Webhook URL exactly
Test returns 401Wrong or missing secretPaste the secret again, or regenerate it and update every machine
Test times outThe machine can't reach AxiaCheck VPN, proxy and firewall rules for the Axia host
Test works, but no prompts arriveCursor started without the variables, or the hook isn't loadedCheck step 3 applied to the login session (on macOS: launchctl getenv AXIA_WEBHOOK_URL), quit and reopen Cursor, check the Hooks tab

Verification Checklist

  • Cursor connected on the Axia Connect page
  • Webhook URL and Webhook Secret saved in your password manager
  • Test curl from a developer machine returns 202
  • Developers informed that prompts are monitored
  • AXIA_WEBHOOK_URL and AXIA_WEBHOOK_SECRET set for the login session on every machine
  • Enterprise hooks.json deployed with "failClosed": false
  • A test prompt shows up in Axia
