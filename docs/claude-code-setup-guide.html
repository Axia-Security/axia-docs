Claude Code Setup Guide

Send the prompts your developers submit in Claude Code to Axia, so sensitive data pasted into an AI coding agent is detected.

What you'll have at the end

A Claude Code hook on each developer machine that forwards every submitted prompt to Axia, using the Webhook URL and Webhook Secret you get on the Connect page in Axia.

Prerequisites

  • Developer machines on macOS or Linux, with python3 on the PATH (standard library only, nothing to install). Windows is not supported yet.
  • Developer machines can reach your Axia Webhook URL over HTTPS (directly, or through your VPN)
  • For a fleet rollout: an MDM or configuration management tool (Jamf, Kandji, Intune, Ansible…) that can place a file on each machine, or a Claude for Teams or Enterprise plan to deploy from the Claude admin console
Tell your developers

Capturing prompts is monitoring of what employees type. Treat it as a policy and consent matter, and tell developers before you turn it on.

1 Connect Claude Code in Axia

  1. In Axia, open Connect and find Claude Code under AI coding.
  2. Click Connect.
  3. Axia shows a Webhook URL and a Webhook Secret. Copy both.
Value to copyLooks like
Webhook URLhttps://<your-axia-host>/api/v1/webhooks/claude_code
Webhook SecretA long random string
The secret is shown once

Save the Webhook Secret in your password manager now. If you lose it, open the connection on the Connect page and click Regenerate secret, then update every machine: the old secret stops working.

2 Check the Webhook URL is reachable

From a developer machine, send a test prompt. Replace the two values with yours:

curl -i -X POST "https://<your-axia-host>/api/v1/webhooks/claude_code" \
  -H "Content-Type: application/json" \
  -H "X-Webhook-Secret: <webhook-secret>" \
  -d '{"event":"user_prompt_submit","timestamp":"2026-01-01T00:00:00Z","project_dir":"/tmp",
       "data":{"user_prompt":"Axia connectivity test","session_id":"setup-test","prompt_id":"1","user":"you@yourcompany.com"}}'

You should get HTTP 202 with "status":"accepted". If not, see Troubleshooting.

3 Deploy the hook

All three options below use the same settings. Copy them and replace the two placeholder values with the ones from step 1:

{
  "env": {
    "AXIA_WEBHOOK_URL": "https://<your-axia-host>/api/v1/webhooks/claude_code",
    "AXIA_WEBHOOK_SECRET": "<webhook-secret>"
  },
  "hooks": {
    "UserPromptSubmit": [
      {
        "hooks": [
          {
            "type": "command",
            "timeout": 10,
            "command": "python3 -c \"import os,sys,json,shutil,subprocess,getpass,datetime as dt,urllib.request; s=os.environ.get('AXIA_WEBHOOK_SECRET',''); url=os.environ.get('AXIA_WEBHOOK_URL',''); (s and url) or sys.exit(0); d=json.load(sys.stdin); e=(subprocess.run(['git','config','user.email'],capture_output=True,text=True).stdout.strip() if shutil.which('git') else ''); u=os.environ.get('AXIA_USER_EMAIL') or e or getpass.getuser(); body=json.dumps({'event':'user_prompt_submit','timestamp':dt.datetime.now(dt.timezone.utc).isoformat(),'project_dir':d.get('cwd',''),'data':{'user_prompt':d.get('prompt',''),'session_id':d.get('session_id',''),'prompt_id':d.get('prompt_id',''),'user':u}}); req=urllib.request.Request(url, data=body.encode(), headers={'Content-Type':'application/json','X-Webhook-Secret':s}, method='POST'); os.fork() or (os.setsid(), urllib.request.urlopen(req,timeout=5), os._exit(0))\" 2>/dev/null || true"
          }
        ]
      }
    ]
  }
}

Use the Claude admin console or MDM option for production: developers cannot remove or override them. Use the per-user option to try it on your own machine first.

Option A — Claude admin console (recommended)

For Claude for Teams and Claude for Enterprise. Claude delivers the settings to every developer who signs in to Claude Code with your organization's account, with no file to deploy.

Open Claude managed settings ↗

  1. Sign in to claude.ai as an Owner or Primary Owner of your Claude organization.
  2. Go to Organization settings > Claude Code > Managed settings (the button above opens it).
  3. Paste the settings above, or merge the env and hooks keys into the settings already there, and save.
Good to know

Developers see a one-time security prompt asking them to approve the hook. Settings from the console only reach sessions signed in with your Claude Teams or Enterprise account. Sessions that use a Claude Console API key, Amazon Bedrock or Google Vertex AI don't receive them: use Option B for those machines.

Option B — Managed settings file (MDM)

Push the settings as a file with your MDM. Claude Code reads it on every machine and it takes precedence over user and project settings. If the file already exists, merge the env and hooks keys into it.

OSPath
macOS/Library/Application Support/ClaudeCode/managed-settings.json
Linux/etc/claude-code/managed-settings.json
Protect the file

The file holds the Webhook Secret. Make it owned by root and not writable by users (for example chown root:wheel and chmod 644 on macOS). The secret only lets a machine send prompts to Axia; it cannot read anything.

Option C — Per-user (for testing)

  1. Merge the settings into ~/.claude/settings.json on your machine.
  2. Restart Claude Code. Run /hooks in Claude Code to check that UserPromptSubmit lists the hook.

A developer can edit or remove this file, so don't rely on it for monitoring.

Which user is the prompt attributed to?

Claude Code does not tell hooks who the user is, so the hook works it out in this order:

  1. The AXIA_USER_EMAIL environment variable, if set
  2. The developer's git config user.email
  3. The operating system login name

For reliable attribution, set AXIA_USER_EMAIL per user through your MDM, or make sure developers' git email is their work email. The same order is used for Cursor, so one person's Claude Code and Cursor prompts match up.

4 Verify

  1. On a machine with the hook, start Claude Code and send any prompt.
  2. In Axia, the Claude Code connection on the Connect page shows a recent event. A prompt containing test sensitive data (for example a fake card number) should open a case.

Troubleshooting

SymptomCauseFix
Test returns 404 Unknown sourceClaude Code is not connected in Axia, or the URL is wrongConnect Claude Code (step 1) and copy the Webhook URL exactly
Test returns 401Wrong or missing secretPaste the secret again, or regenerate it on the Connect page and update every machine
Test times outThe machine can't reach AxiaCheck VPN, proxy and firewall rules for the Axia host
Test works, but no prompts arriveThe hook isn't loaded, or the variables are emptyRun /hooks in Claude Code; check the env block; check python3 --version works in a terminal
Prompts are attributed to a login name, not an emailNo AXIA_USER_EMAIL and no git emailSet AXIA_USER_EMAIL or the developer's git email

Verification Checklist

  • Claude Code connected on the Axia Connect page
  • Webhook URL and Webhook Secret saved in your password manager
  • Test curl from a developer machine returns 202
  • Developers informed that prompts are monitored
  • Settings deployed from the Claude admin console, or as a managed settings file by MDM (owned by root)
  • AXIA_USER_EMAIL set, or developers' git email is their work email
  • A test prompt shows up in Axia
