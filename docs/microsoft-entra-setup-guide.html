Microsoft Entra ID Setup Guide

Configure your Microsoft 365 tenant so Axia can monitor Outlook emails and Teams messages for DLP analysis.

What you'll have at the end

An app registration in your Microsoft Entra ID with the right permissions, and four values you enter yourself on the Connect page in the Axia app: Directory (tenant) ID, Application (client) ID, Client Secret Value, and your Primary domain.

Prerequisites

  • A Microsoft 365 tenant with an active subscription (Business Basic or higher)
  • Global Administrator or Application Administrator role in Entra ID
  • Access to the Azure Portal

1 Register the Application

  1. Sign in to the Azure Portal.
  2. Navigate to Microsoft Entra ID > App registrations.
  3. Click + New registration.
  4. Fill in the form:
    • Name: Axia Security
    • Supported account types: Accounts in this organizational directory only (Single tenant)
    • Redirect URI: Leave blank
  5. Click Register.

After registration, copy these values from the Overview page:

Value to copyWhere to find it
Application (client) IDOverview page, top section
Directory (tenant) IDOverview page, top section

2 Create a Client Secret

  1. In the app registration, go to Certificates & secrets > Client secrets.
  2. Click + New client secret.
  3. Enter a description (e.g., Axia production) and choose an expiry (recommended: 24 months).
  4. Click Add.
  5. Immediately copy the Value column.
Value to copy
Secret Value (the long string — not the Secret ID)
Important

Copy the Value, not the Secret ID. The Secret ID is a UUID that identifies the secret — it cannot be used for authentication. The Value is only shown once.

3 Grant API Permissions

Axia uses Microsoft Graph API with application permissions (no user sign-in required).

  1. In the app registration, go to API permissions.
  2. Click + Add a permission > Microsoft Graph > Application permissions.
  3. Add the permissions listed below for each Microsoft service you plan to enable in Axia (Outlook, Teams, Purview DLP). One app registration can serve all three.

Microsoft Outlook (email monitoring)

PermissionRequiredPurpose
Mail.ReadYesReading sent mail and its attachments
User.Read.AllYesListing the mailboxes to monitor
Files.ReadWrite.AllOptionalFollowing OneDrive and SharePoint share links found in email, and revoking a link when an operator decides to. Microsoft has no read-only permission for opening a share link as an app. Revoking switches the link off; it does not delete, change, move or copy the file.

Microsoft Teams (message monitoring, if enabled)

PermissionRequiredPurpose
Chat.Read.AllYesReading chat messages
ChannelMessage.Read.AllYesReading channel messages
Team.ReadBasic.AllYesListing the teams each user belongs to
Channel.ReadBasic.AllYesListing the channels in each team
User.Read.AllYesListing the users to monitor
Files.Read.AllOptionalDownloading files attached to chat messages (stored in OneDrive and SharePoint). Links posted in chats are not followed.

Microsoft Purview DLP (DLP alerts, if enabled)

PermissionRequiredPurpose
SecurityAlert.Read.AllYesReading Purview DLP alerts

Axia doesn't check this permission when you connect. If it's missing or not consented, Purview DLP still connects but receives no alerts. New or changed DLP policies can take up to about 3 hours to start generating alerts.

  1. After adding all needed permissions, click Grant admin consent for [Your Organization].
  2. Confirm by clicking Yes.
  3. Verify that every permission shows a green checkmark under Status.
Admin consent is required

Without admin consent, the application will receive 403 Forbidden errors when calling the Graph API.

4 Identify Your Organization Domain

Axia uses the organization domain to distinguish internal recipients from external recipients. By default, only emails sent to external recipients are analyzed.

  1. In the Azure Portal, go to Microsoft Entra ID > Custom domain names.
  2. Look for the domain marked as Primary.
Value to copy
Primary domain (e.g., yourcompany.com)

5 Connect Microsoft 365 in Axia

Enter the values from the previous steps directly in the Axia app. You don't need to send them to anyone.

Outlook, Teams and Purview DLP share one app registration, so Axia connects them together from a single Microsoft 365 card. You enter the credentials once and choose which services to enable.

  1. Sign in to the Axia app and go to Setup > Connect.
  2. On the Available tab, open the Microsoft 365 card under SaaS Applications.
  3. Enter the shared credentials:
Field in AxiaValue from Entra IDWhere you copied it
Tenant IDDirectory (tenant) IDStep 1 — Overview page
Client IDApplication (client) IDStep 1 — Overview page
Client SecretClient Secret ValueStep 2 — Certificates & secrets
  1. Choose the services to enable. Outlook, Teams and Purview DLP are all selected by default. Turn off any service whose permissions you didn't grant in Step 3.
  2. Enter your Organization Domain, the primary domain from Step 4 (for example yourcompany.com). The field is always shown and is required.
  3. Optionally, turn on Scan Inbound Emails to analyze incoming mail too.
  4. Click Test & Connect. Axia checks the credentials and the required permissions for each selected service before saving.
"Partially connected"

Each selected service is checked separately. If some connect and others fail, for example Teams without Team.ReadBasic.All, the result is Partially connected, and the error names the missing permissions. The services that passed stay connected. Grant the missing permissions with admin consent (Step 3), then connect the failed service again.

After you connect, each enabled service has its own card on the Connected tab showing its status (for example Healthy). Expand Permissions on a card to see which Graph permissions Axia has confirmed as Granted.

Keep the secret in Axia

Paste the Client Secret Value straight into Axia. Don't send it by email or chat. The secret expires on the date you chose in Step 2. Changing it from the Axia app isn't supported yet for Microsoft connections, so contact your Axia deployment team before the secret expires.

Verification Checklist

  • App registration exists in Microsoft Entra ID
  • Application (client) ID and Directory (tenant) ID copied from Overview page
  • Client Secret Value is the secret Value (not the Secret ID)
  • Every required permission from Step 3 is added for each service you enabled: Outlook Mail.Read, User.Read.All; Teams Chat.Read.All, ChannelMessage.Read.All, Team.ReadBasic.All, Channel.ReadBasic.All, User.Read.All; Purview DLP SecurityAlert.Read.All
  • Admin consent is granted (green checkmarks on all permissions)
  • Only services with granted permissions are selected on the Microsoft 365 card
  • Organization Domain in Axia matches your primary email domain
  • Every enabled Microsoft service (Outlook, Teams, Purview DLP) shows Healthy on the Connected tab, and all its required permissions show Granted
