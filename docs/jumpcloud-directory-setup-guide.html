JumpCloud Directory Setup Guide

Keep Axia's employee directory in sync with the people you manage in JumpCloud: names, departments, job titles, locations and managers.

What you'll have at the end

A JumpCloud Directory connection on the Axia Connect page. Axia reads your JumpCloud users right after you connect and every hour after that, and uses them as the org directory instead of an uploaded CSV. Axia only reads; it never changes anything in JumpCloud.

Prerequisites

  • A JumpCloud administrator who can create service accounts
  • An Axia administrator account
  • No other directory (Microsoft Entra ID or Google Workspace) connected in Axia. Axia uses one directory at a time
One JumpCloud organization

This guide connects a single JumpCloud organization, with a service account created in that organization's Admin Portal. Organizations managed from JumpCloud's Multi-Tenant Portal (MTP) are not supported yet: MTP service accounts sign in with a client ID and secret, which Axia does not accept. If you manage your organization through the MTP, contact Axia support.

Use a service account with the Read Only role

Give Axia its own JumpCloud service account rather than a person's API key: it keeps working when people leave, and its role limits what the key can do. The Read Only role is enough; Axia only reads users. If you regenerate the key, update it in Axia.

1 Create a service account and its API key

  1. Sign in to the JumpCloud Admin Portal.
  2. Go to Settings > Service Accounts and create a service account for Axia, for example axia-directory-sync.
  3. Give it the Read Only role.
  4. Copy its API key (it starts with jcs_) and store it in your password manager; JumpCloud shows it only once.

2 Check your region

You sign in atRegion in Axia
console.jumpcloud.comUS
console.eu.jumpcloud.comEU

3 Connect in Axia

  1. In Axia, open Connect and choose JumpCloud Directory.
  2. Paste the API Key.
  3. Leave Organization ID blank.
  4. Choose the Region from step 2.
  5. Choose Connect. Axia reads one user to check the key before saving the connection.

The first sync starts at once. Its progress and result show in Settings > Organization relations.

Troubleshooting

Message in AxiaCauseFix
JumpCloud refused the API keyThe key was regenerated or mistyped, the region is wrong, or an Organization ID was enteredCheck the region (step 2) and leave Organization ID blank; if needed, create a new key (step 1), then edit the connection
The API key cannot read usersThe service account's role can't read usersGive the service account the Read Only role or above
A directory is already connectedMicrosoft Entra ID or Google Workspace is the directoryDisconnect it first; Axia uses one directory at a time
People have no managerThe manager isn't set in JumpCloud, or is a user outside this organizationSet the user's manager in JumpCloud; the next hourly sync picks it up
JumpCloud could not be reachedA network problemAxia retries on the next sync

Verification Checklist

  • A JumpCloud service account with the Read Only role created for Axia
  • API key saved in your password manager
  • JumpCloud Directory connected on the Axia Connect page with the right region
  • Settings > Organization relations shows JumpCloud with your people count
  • A few people spot-checked for department, job title and manager
