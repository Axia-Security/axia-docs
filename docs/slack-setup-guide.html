Slack setup guide

Connect a Slack workspace so Axia Security reads the channels its app is in that include someone from outside your organization. You create the Axia Security app in your own Slack from a manifest Axia Security generates, install it, and paste its two credentials on the Connect screen.

What you need. An Axia Security administrator account (the Connect screen is for administrators), and permission in Slack to create and install apps in your workspace.

Where to start. Open Slack on the Connect screen. The same steps are shown there, above the credential fields.

What Axia Security does in Slack

Axia Security reads the messages in the Slack channels its app is in, and the files shared there, including their content — but only while someone from outside your organization is in the channel. It does not read direct messages or any other channel.

Axia Security never posts or reacts in Slack. Its app joins channels by itself only if you turn on All public channels (step 11).

Reading starts once you finish steps 10 to 12, and stops when you remove the Slack connection on the Connect screen.

Why the app asks for each permission

The manifest asks for these eight permissions and nothing else. Connect checks each one; channels:join is needed only if you turn on All public channels.

PermissionWhy
channels:historyReading messages in the public channels the Axia Security bot was added to
groups:historyReading messages in the private channels the Axia Security bot was added to
channels:readReading the name and sharing of the public channels the bot is in
groups:readReading the name and sharing of the private channels the bot is in
users:readTelling members, guests and people from outside the organization apart
users:read.emailReading each author's email address, to match them to the employee directory
files:readReading the files shared in those channels, including their content
channels:joinJoining public channels by itself. Nothing is joined unless you turn on All public channels.

Set up the Axia Security app in Slack

1. Copy the Axia Security app manifest

On the Connect screen, select Copy manifest. If your browser does not allow copying, select Download manifest and open the file in a text editor. Keep the Connect window open: after you create the app in Slack, you come back to it to paste two values from the app.

2. Start a new app in Slack

Open api.slack.com/apps in a new tab, sign in to your Slack workspace if Slack asks, and select Create an App.

3. Create the app from the manifest

Select From a manifest, then Continue. On the next screen choose the YAML tab, delete the example text, paste the manifest you copied in step 1, choose your workspace and select Next.

4. Install the app in your workspace

Slack shows a summary of the app. Select Create and Install, then Allow if Slack asks.

5. Open the app's settings

Slack shows “Axia Security is ready!” with Slack CLI steps. You don't need them: select Go to App Settings. Keep this Slack tab open.

6. Copy the Signing Secret

In the app's settings, select Basic Information in the left menu. Under App Credentials, next to Signing Secret, select Show, then copy the value. Copy the Signing Secret, not the Client Secret or the Verification Token beside it.

7. Paste the Signing Secret on the Connect screen

Come back to the Connect window and paste it into the Signing Secret field at the bottom.

8. Copy the Bot User OAuth Token

In the Slack tab, select OAuth & Permissions in the left menu. Under OAuth Tokens, next to Bot User OAuth Token (it starts with xoxb-), select Copy.

9. Paste the token on the Connect screen and connect

Come back to the Connect window, paste it into the Bot User OAuth Token field at the bottom and select Test & Connect. The steps left then appear on the Connect screen.

Axia Security checks the token with Slack and checks that the app has every read permission listed above. If a permission is missing, Connect names it (see If something does not work).

You paste both values directly on the Connect screen; nobody needs to send them to Axia Security by email.

Finish in Slack

After Test & Connect, the Connect screen shows Credentials saved and steps 10 to 12. Once step 10 is done and Slack reaches Axia Security, it changes to Slack connected.

10. Verify the events address in Slack

In the Slack tab, select Event Subscriptions in the left menu. The Request URL may first show “Your URL didn't respond”: that is expected (Slack tried it before Axia Security had your secret). Select Retry (or Verify); it turns Verified. Then select Save Changes at the bottom of the page.

11. Choose whether the app joins every public channel

The All public channels switch is off by default. Turn it on, and confirm with Turn on, if you want the app to join every public channel in the workspace, including new ones, instead of adding it to channels yourself. Axia Security still reads only the channels that include someone from outside your organization.

Joining starts within two hours, and Slack shows the app joining each channel. Turning the switch off stops new joins; the app stays in the channels it already joined. To take it out of every channel, remove the app in Slack. You can change the switch later under Manage on the Slack card.

12. Add the app to channels (if "All public channels" is off)

In the channel, type /invite @Axia and choose Axia Security from the list that appears (public and private channels alike). Or open the channel's details → Integrations (in newer Slack: Agents & apps) → Add an app → Axia Security. You need permission to invite people in that channel; if Slack says you don't have it, ask the channel's manager or a workspace admin, or use a channel you created. Axia Security reads a channel only while someone from outside your organization is in it; remove the app from a channel to stop.

On the Connect screen, select Done when you have finished. The list Slack channels Axia Security reads is an optional check: it shows the channels read now, marked Private or Shared with another organization where that applies. Select Refresh to update it.

If something does not work

Connect says "Missing required permissions"

The app in Slack does not have every permission Axia Security reads with; Connect names each one that is missing. In your app's settings, open OAuth & Permissions → Scopes and add each permission named. Reinstall the app to your workspace, then select Test & Connect again.

Slack says "Your URL didn't respond"

Slack tried the Request URL before Axia Security had your Signing Secret, which is expected the first time. Select Retry next to the Request URL; once it shows Verified, select Save Changes. If it still does not respond, the most common reason is that the secret pasted on the Connect screen is the Client Secret or the Verification Token instead of the Signing Secret: on the Connect screen select Manage on the Slack card, paste the Signing Secret from Basic Information → App Credentials again and select Save changes, then select Retry in Slack. If it still does not turn Verified, contact Support.

Slack says "You don't have permission to invite people to this channel"

Adding the app to a channel needs permission to invite people to that channel. Ask the channel's manager or a workspace admin to add the Axia Security app there, or use a channel you created.

"All public channels" cannot be turned on

The app in Slack is missing what this option needs, usually because it was created from an older manifest. Update it from the current one: on the Connect screen, copy the manifest again (step 1); in your app's settings, select App Manifest in the left menu, replace the text with the manifest you copied and save. Reinstall the app to your workspace. Then, on the Connect screen, open the Slack card's menu (⋮) and select Test. The same fix applies if the Connect screen says the app no longer has channels:join.

The Slack card says "Awaiting first event"

The connection is saved, but Slack has not reached Axia Security yet. Check that the Request URL shows Verified (step 10). It clears as soon as Slack reaches Axia Security.

The Slack card says "No messages for 24 h"

Nothing has reached Axia Security from Slack in the last 24 hours. A quiet channel or a weekend can cause it. Check that the app is still in its channels (or that All public channels is on) and that the Request URL still shows Verified. It clears when Slack next reaches Axia Security.

Verification checklist

  • The app is created from the Axia Security manifest and installed to your workspace (Create and Install).
  • The Signing Secret (not the Client Secret) and the Bot User OAuth Token (xoxb-) are pasted, and Test & Connect succeeded.
  • The Request URL shows Verified under Event Subscriptions, and you selected Save Changes.
  • All public channels is on, or the Axia Security app is in each channel it should read (step 12).
  • After step 10, the Connect screen shows Slack connected, and the Slack card does not say Awaiting first event.
