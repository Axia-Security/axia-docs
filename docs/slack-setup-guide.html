Slack Setup Guide

Connect your Slack workspace so Axia can monitor the messages and files shared in the channels you choose for DLP analysis.

What you'll have at the end

An Axia Security app in your Slack workspace, connected to Axia with two values: its Signing Secret and its Bot User OAuth Token. Axia reads the channels you add the app to, and nothing else.

How it works

  • You create the Axia Security app in your own Slack workspace from a manifest that Axia generates. Nothing is installed from an app directory.
  • Slack sends Axia an event each time someone posts, edits or deletes a message in a channel the app is a member of. Axia then reads the files shared in that message.
  • Axia reads only the channels you add the app to, public or private. It does not read direct messages, group DMs or any other channel.
  • Axia never posts, reacts or changes anything in Slack. The app asks for read permissions only.
  • Messages from bots and apps are ignored. Edits and deletions are recorded on the case.

Prerequisites

  • A Slack workspace on any paid or free plan
  • Permission to create and install apps in the workspace (a Workspace Admin or Owner, or a member if your workspace allows members to install apps)
  • An Admin account in Axia, to open the Connect page
  • Your Axia events address must be reachable from the internet over HTTPS, because Slack delivers events to it. Hosted Axia already is. For a self-hosted deployment, see the Deployment guide.
Enterprise Grid

The Connect page also lists an Enterprise Grid option that reads a whole Slack organization, including private channels and DMs, without adding a bot to each channel. It is marked Coming soon. Until it is available, use the standard (bot) option described here. It works on Enterprise Grid too, one workspace at a time.

1 Start the connection in Axia

  1. In Axia, open Connect and find Slack.
  2. Click Connect. If Axia asks how to connect, choose Standard (bot).
  3. Select Copy manifest. If your browser does not allow copying, select Download manifest and open the file in a text editor.
Keep this window open

After you create the app in Slack you come back to this form to paste two values from it.

2 Create the app in Slack

  1. Open api.slack.com/apps in a new tab and sign in to your workspace if Slack asks.
  2. Click Create an App, then From a manifest, then Continue.
  3. Choose the YAML tab, delete the example text and paste the manifest you copied.
  4. Choose your workspace and click Next.
  5. Slack shows a summary of the app. Click Create and Install, then Allow if Slack asks.
  6. Slack shows “Axia Security is ready!” with Slack CLI steps. You don't need them: click Go to App Settings. Keep this tab open.

What the manifest asks for

The manifest creates a bot named axia-security with these read-only permissions (bot token scopes):

ScopePurpose
channels:historyRead messages in the public channels the bot was added to
groups:historyRead messages in the private channels the bot was added to
channels:readRead the name and sharing of the public channels the bot is in
groups:readRead the name and sharing of the private channels the bot is in
users:readTell members, guests and people from outside the organization apart
users:read.emailRead each author's email address, to match them to your employee directory
files:readRead the files shared in those channels, including their content

It also subscribes the app to these events:

EventWhy
message.channelsMessages in public channels the bot is in
message.groupsMessages in private channels the bot is in
channel_shared / channel_unsharedA channel starts or stops being shared with another organization (Slack Connect), which changes who can see it

3 Copy the two credentials into Axia

Copy and paste one value at a time: your clipboard holds one value.

  1. In the Slack app settings, open Basic Information. Under App Credentials, next to Signing Secret, click Show and copy the value.
  2. Back in Axia, paste it into the Signing Secret field.
  3. In Slack, open OAuth & Permissions. Under OAuth Tokens, copy the Bot User OAuth Token (it starts with xoxb-).
  4. Back in Axia, paste it into the Bot User OAuth Token field and click Test & Connect.
Value to copyWhere to find itLooks like
Signing SecretBasic Information > App Credentials32 hex characters
Bot User OAuth TokenOAuth & Permissions > OAuth Tokensxoxb-…
Important

Copy the Signing Secret, not the Client Secret or the Verification Token next to it. Copy the Bot token (xoxb-), not a user token (xoxp-). Axia checks the token and its scopes when you click Test & Connect.

4 Verify the events address in Slack

  1. In the Slack app settings, open Event Subscriptions.
  2. The Request URL may show “Your URL didn't respond”. That is expected: Slack tried it before Axia had your Signing Secret.
  3. Click Retry (or Verify). It turns Verified.
  4. Click Save Changes at the bottom of the page.

5 Add the app to the channels Axia should read

Axia reads exactly the channels the app is a member of. Repeat this for each channel, public or private:

  • In the channel, type /invite @Axia and choose Axia Security from the list, or
  • Open the channel's details > Integrations (in newer Slack: Agents & apps) > Add an app > Axia Security.

You need permission to invite people to the channel. If Slack says you don't have it, ask the channel's manager or a workspace admin.

Done

Back in Axia, click Done. The channel list on the connection shows the channels the app is in, as a check. To stop reading a channel, remove the app from it in Slack. To stop entirely, remove the connection in Axia and uninstall the app in Slack.

Connection status

Axia cannot test the Signing Secret from the Connect page, so it marks the connection healthy only once messages arrive.

Status on the Connect pageMeaningWhat to do
Awaiting first eventNo message has arrived yetCheck step 4 shows Verified, check step 5 for at least one channel, then post a test message there
No messages for 24 hNothing has arrived for a dayNormal for quiet channels or weekends. Otherwise check the app is still installed and in the channels
Status unavailableAxia could not read the statusTry again later. Contact Support if it persists

Troubleshooting

  • Test & Connect reports missing permissions. The app was created from an older or edited manifest. In Slack, open OAuth & Permissions, add the missing scopes under Bot Token Scopes, click Reinstall to Workspace, then paste the token again.
  • The Request URL never verifies. Check the Signing Secret in Axia matches the one in Slack (edit the connection to paste it again). For self-hosted deployments, check the events address is reachable from the internet over HTTPS.
  • Messages in a channel are missing. Make sure the app is a member of that channel. Messages posted before the app joined are not read.
  • Direct messages are not monitored. This is by design for the standard (bot) option.

Verification Checklist

  • Axia Security app created in Slack from the manifest copied from Axia
  • App installed to the workspace
  • Signing Secret pasted (not the Client Secret or Verification Token)
  • Bot User OAuth Token (xoxb-) pasted and Test & Connect succeeded
  • Event Subscriptions Request URL shows Verified and changes are saved
  • App added to every channel Axia should read
  • A test message posted in one of those channels, and the connection no longer shows Awaiting first event
