Slack setup guide

Connect a Slack workspace so AXIA reads the channels you add its app to. You create the AXIA app in your own Slack from a manifest AXIA generates, install it, and paste its two credentials on the Connect screen.

What you need. An AXIA administrator account (the Connect screen is for administrators), and permission in Slack to create and install apps in your workspace.

Where to start. Open Slack on the Connect screen. The same steps are shown there, above the credential fields.

What AXIA does in Slack

AXIA reads the messages and files in the Slack channels you add its app to — nothing else. It does not read direct messages or any other channel.

AXIA never posts, reacts or changes anything in Slack.

Reading starts as soon as you save the Slack connection on the Connect screen and stops when you remove it.

Why the app asks for each permission

The manifest asks for these seven read permissions and nothing else. Connect checks that the app has each of them.

PermissionWhy
channels:historyReading messages in the public channels the AXIA bot was added to
groups:historyReading messages in the private channels the AXIA bot was added to
channels:readReading the name and sharing of the public channels the bot is in
groups:readReading the name and sharing of the private channels the bot is in
users:readTelling members, guests and people from outside the organization apart
users:read.emailReading each author's email address, to match them to the employee directory
files:readReading the name, type and size of files shared in those channels

Set up the AXIA app in Slack

1. Get the AXIA app manifest

On the Connect screen, select Copy manifest or Download manifest. If your browser does not allow the copy, download the manifest instead.

2. Create the app in Slack from the manifest

Open api.slack.com/apps, select Create New App → From a manifest, choose your workspace and paste the manifest. If you downloaded it, paste the file's contents.

3. Install the app to your workspace

Select Install to Workspace and allow it. The app asks only to read the channels you add it to.

4. Copy the two credentials

Value to copyWhere it is in your app's settings
Signing SecretBasic Information → App Credentials
Bot User OAuth Token (it starts with xoxb-)OAuth & Permissions

Important. Under App Credentials, copy the Signing Secret, not the Client Secret or the Verification Token.

5. Paste them on the Connect screen and select Test & Connect

AXIA checks the token with Slack and checks that the app has every permission listed above. If a permission is missing, Connect names it (see If something does not work).

You paste both values directly on the Connect screen; nobody needs to send them to AXIA by email.

Finish in Slack

Once the connection is saved, the Connect screen shows two more steps and the list Slack channels AXIA reads.

6. Verify the events address in Slack

In your app's settings, open Event Subscriptions and select Verify (or Retry) next to the Request URL. It turns Verified once AXIA answers.

7. Add @axia-security to each channel AXIA should read

In the channel, type /invite @axia-security (public and private channels alike). AXIA reads exactly the channels the app is in; remove it from a channel to stop.

The list Slack channels AXIA reads shows what Slack says the app is in right now, and marks channels that are Private or Shared with another organization. Select Refresh after you add the app to a channel.

If something does not work

Connect says "Missing required permissions"

The app in Slack does not have every permission AXIA reads with; Connect names each one that is missing. In your app's settings, open OAuth & Permissions → Scopes and add each permission named. Reinstall the app to your workspace, then select Test & Connect again.

The Slack card says "Awaiting first event"

The connection is saved, but no message has reached AXIA yet. Check that the Request URL shows Verified (step 6) and that the app is in at least one channel (step 7). It clears when the first message arrives in a channel the app is in.

The Slack card says "No messages for 24 h"

No message has reached AXIA from the workspace in the last 24 hours. A quiet channel or a weekend can cause it. Check that the app is still in the channels AXIA should read and that the Request URL still shows Verified. It clears when the next message arrives.

The Request URL in Slack does not show Verified

Slack has not had an answer from AXIA yet. Select Retry next to the Request URL. If it still does not turn Verified, contact Support.

Verification checklist

  • The app is created from the AXIA manifest and installed to your workspace.
  • The Signing Secret (not the Client Secret) and the Bot User OAuth Token (xoxb-) are pasted, and Test & Connect succeeded.
  • The Request URL shows Verified under Event Subscriptions.
  • @axia-security is in each channel AXIA should read, and those channels appear under Slack channels AXIA reads.
  • After the first message in one of those channels, the Slack card no longer says Awaiting first event.
