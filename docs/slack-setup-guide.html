Slack setup guide

Connect a Slack workspace so Axia Security reads the channels you add its app to. You create the Axia Security app in your own Slack from a manifest Axia Security generates, install it, and paste its two credentials on the Connect screen.

What you need. An Axia Security administrator account (the Connect screen is for administrators), and permission in Slack to create and install apps in your workspace.

Where to start. Open Slack on the Connect screen. The same steps are shown there, above the credential fields.

What Axia Security does in Slack

Axia Security reads the messages in the Slack channels you add its app to, and the name, type and size of files shared there — nothing else. File contents are not read yet, and it does not read direct messages or any other channel.

Axia Security never posts, reacts or changes anything in Slack.

Reading starts once Slack has verified the events address (step 6, shown after you connect) and the app is in a channel (step 7). It stops when you remove the Slack connection on the Connect screen.

Why the app asks for each permission

The manifest asks for these seven read permissions and nothing else. Connect checks that the app has each of them.

PermissionWhy
channels:historyReading messages in the public channels the Axia Security bot was added to
groups:historyReading messages in the private channels the Axia Security bot was added to
channels:readReading the name and sharing of the public channels the bot is in
groups:readReading the name and sharing of the private channels the bot is in
users:readTelling members, guests and people from outside the organization apart
users:read.emailReading each author's email address, to match them to the employee directory
files:readReading the name, type and size of files shared in those channels

Set up the Axia Security app in Slack

1. Get the Axia Security app manifest

On the Connect screen, select Copy manifest or Download manifest. If your browser does not allow the copy, download the manifest instead. If you download it, you paste the file's contents on Slack's YAML tab in step 2. Keep the Connect window open: you paste the credentials into it in step 5.

2. Create the app in Slack from the manifest

Open api.slack.com/apps and select Create an App → From a manifest → Continue. On the next screen choose the YAML tab, replace the example with the manifest, choose your workspace and select Next. Review the app and select Create and Install (and Allow if Slack asks).

3. Open the app's settings

Slack shows “Axia Security is ready!” with Slack CLI steps: skip them and select Go to App Settings. Keep this Slack tab open — you come back to it in steps 4 and 6.

4. Copy the two credentials

Value to copyWhere it is in your app's settings
Signing SecretBasic Information → App Credentials → Show, then copy
Bot User OAuth Token (it starts with xoxb-)OAuth & Permissions → OAuth Tokens → Copy

Important. Copy the Signing Secret, not the Client Secret or the Verification Token beside it.

5. Paste them on the Connect screen and select Test & Connect

Paste each into its field at the bottom of the Connect window, below step 5: Signing Secret and Bot User OAuth Token. Then select Test & Connect.

Axia Security checks the token with Slack and checks that the app has every permission listed above. If a permission is missing, Connect names it (see If something does not work).

You paste both values directly on the Connect screen; nobody needs to send them to Axia Security by email.

Finish in Slack

After Test & Connect, the Connect screen says: "Slack is connected. Reading starts once you finish steps 6 and 7 in Slack." It then shows steps 6 and 7 and the list Slack channels Axia Security reads.

6. Verify the events address in Slack

In your app's settings open Event Subscriptions. The Request URL may first show “Your URL didn't respond”: that is expected (Slack tried it before Axia Security had your secret). Select Retry (or Verify); it turns Verified. Then select Save Changes at the bottom of the page.

7. Add @axia-security to each channel Axia Security should read

In the channel, type /invite @axia-security (public and private channels alike). You need permission to invite people in that channel; if Slack says you don't have it, ask the channel's manager or a workspace admin, or use a channel you created. Axia Security reads exactly the channels the app is in; remove it from a channel to stop.

On the Connect screen, select Done when you have finished. The list Slack channels Axia Security reads is an optional check: it shows what Slack says the app is in right now, and marks channels that are Private or Shared with another organization. Select Refresh after you add the app to a channel.

If something does not work

Connect says "Missing required permissions"

The app in Slack does not have every permission Axia Security reads with; Connect names each one that is missing. In your app's settings, open OAuth & Permissions → Scopes and add each permission named. Reinstall the app to your workspace, then select Test & Connect again.

Slack says "Your URL didn't respond"

Slack tried the Request URL before Axia Security had your Signing Secret, which is expected the first time. Select Retry next to the Request URL; once it shows Verified, select Save Changes. If it still does not respond, the most common reason is that the secret pasted on the Connect screen is the Client Secret or the Verification Token instead of the Signing Secret: on the Connect screen select Manage on the Slack card, paste the Signing Secret from Basic Information → App Credentials again and select Save changes, then select Retry in Slack. If it still does not turn Verified, contact Support.

Slack says "You don't have permission to invite people to this channel"

Adding the app to a channel needs permission to invite people to that channel. Ask the channel's manager or a workspace admin to type /invite @axia-security there, or use a channel you created.

The Slack card says "Awaiting first event"

The connection is saved, but no message has reached Axia Security yet. Check that the Request URL shows Verified (step 6) and that the app is in at least one channel (step 7). It clears when the first message arrives in a channel the app is in.

The Slack card says "No messages for 24 h"

No message has reached Axia Security from the workspace in the last 24 hours. A quiet channel or a weekend can cause it. Check that the app is still in the channels Axia Security should read and that the Request URL still shows Verified. It clears when the next message arrives.

Verification checklist

  • The app is created from the Axia Security manifest and installed to your workspace (Create and Install).
  • The Signing Secret (not the Client Secret) and the Bot User OAuth Token (xoxb-) are pasted, and Test & Connect succeeded.
  • The Request URL shows Verified under Event Subscriptions, and you selected Save Changes.
  • @axia-security is in each channel Axia Security should read, and those channels appear under Slack channels Axia Security reads.
  • After the first message in one of those channels, the Slack card no longer says Awaiting first event.
